# ZPP011 生产偏差分析器 · 界面体系全面分析与设计思路

> 版本：设计稿 v43.333 | 日期：2026-11-10 | 范围：主界面 + 11 个看板 + 30+ 弹窗 + 规则配置体系
> 方法论：ui-ux-pro-max 设计系统检索（Pattern: Data-Dense + Drill-Down / Style: Data-Dense Dashboard）
> 本文所有诊断均来自当前源码实读，关键处标注了文件与行号。

---

## 一、结论先说

整套软件的界面**不是"不够好看"，而是"没有统一的设计系统"**。三个层次的问题同时存在：

1. **视觉层分裂** —— 同一个软件里同时存在 **三种蓝**：主窗口 `#3B5BDB`（靛蓝，上一轮刚改）、看板 `#0969da`（GitHub 蓝）、旧样式 `#0078d7`（微软蓝）。同时 5 个表格看板写死了浅色 QSS，**开暗色主题时看板依然是亮的**，用户会当场看出"进了一个网页"。
2. **信息架构层失控** —— 同一个功能有三个入口（菜单栏 / 工具栏下拉 / KPI 卡片点击），看板顶部筛选栏为了塞下 13 个控件而**横向滚动**，源码注释里明明白白写着"1400px 窗口下 13 个控件有 8 个不可见"（`neg_loss_dashboard_dialog.py:86`）。规则配置散在 4 个文件、4 个入口。
3. **架构层复制粘贴** —— 5 个表格看板（`neg_loss` 1489 行、`pos_loss` 1517 行、`semi` 1508 行、`deviation_warning` 1852 行）各自独立实现了几乎一样的筛选栏脚手架，合计 6400+ 行；任何一次 UI 调整要改 5 遍，这是所有"不敢动看板样式"的根因。

**核心判断：先做壳（Shell），再做皮（Skin）。** 建一个统一的看板外壳 + 弹窗外壳 + 规则外壳，把 11 个看板和 30 个弹窗的公共结构抽出来收敛，样式问题会自然消解一大半；反之如果继续逐个改 QSS，会陷入"改完这个那个塌了"的历史循环。

## 三、深度诊断（现象 → 代码证据 → 影响 → 根因）

### D1 · 看板与主窗口主题割裂（视觉级致命）

**现象**：主窗口切到暗色后，5 个表格看板仍然是亮的白底。

**代码证据**：`gui_pyside6/widgets/board_visual.py:44` 的 `BOARD_QSS` 是**写死的局部样式表**，`QDialog#zppBoardDialog { background-color: #f4f7fb; }`，整段只写浅色值（`#0969da` 蓝、`#eef4fb` 表头、`#f7fafd` 斑马纹）。文件头注释写明"作用域限定，不污染主窗口的 light/dark 全局主题"——**于是它自己也没了暗色**。

**影响**：用户点开看板的瞬间，"同一个软件两个界面"。这是暗色主题一直被诟病但改不掉的直接原因，也是这次设计必须解决的第一优先级。

**根因**：看板没有纳入全局主题体系，只能自带一套局部 QSS 兜底。

---

### D2 · 看板筛选栏横向滚动（可用性级致命）

**现象**：5 个看板顶部筛选区要横向拖动才能看全，实际显示不全。

**代码证据**（`neg_loss_dashboard_dialog.py:86-89`）：

```python
# v43.139：顶部重排四行（实测单行需 3153px，1400px 窗口下 13 个控件有 8 个不可见）
# v43.143：颜色标记独占一行，顶部变五行（实测五行需 186px）
scroll.setMinimumHeight(186)
scroll.setMaximumHeight(194)
```

**实测数据**：单行需要 3153px，正常窗口 1400px。意味着**用户想看「车间」筛选器，得先把滚动条拖到最右边**，而「车间」「工厂」「单位」这些正是排查问题最常用的维度。

**连带伤害**：这个筛选栏成了雷区。`board_visual.py:12-15` 的约束写得很清楚：

> **只改观感，不改布局尺寸**：顶部筛选栏的宽度是 v43.139/v43.143/v43.154 逐像素精算过的（1150px 窗口差 11px 就重叠），任何会改 sizeHint 的规则都可能让 13 个筛选控件互相压住。

因为给控件写 `padding` 就会改变 `sizeHint`（实测按钮 80×20 → 24×12），所以看板**连圆角和内边距都不敢加**。这就是"看板看起来和主窗口不像一个软件"的直接原因，也是长期没人敢美化看板的原因。

**根因**：筛选维度没有分层——13 个平级控件硬挤在一行，没有"常用/更多"之分。

---

### D3 · 看板筛选维度与主界面重复且状态割裂

**现象**：主界面左栏 260px 里有过滤/筛选/快捷/备选料（`components/left_panel.py`），右边还有独立 440px 筛选面板（`filter_panel.py`），两者功能重叠且各自一个开关按钮（`layout_composer.py:126-152` 的「左侧栏」「筛选」「列头筛选」）。

**影响**：三个独立开关 → 用户不知道"我现在开着什么"，切来切去找不到条件。

**根因**：没有"筛选抽屉"这个统一概念。

---

### D4 · 规则配置是线性长表单，且布局会跳动

**现象**：自动隔离规则编辑区是一个从上到下的长列表：规则名称 → 启用 → 名称包含 → 类别复选框组 → 排除替代料 → 要求负损 → 偏差率区间 → 编码前缀 → 车间 → **单位 20 个复选框** → 备注要求 → 名称不含 → 偏差数量区间 → 规则预览。

**代码证据**（`auto_quarantine_rule_dialog.py:99-104, 146-165`）：

```python
self.chk_cat = QCheckBox("要求属于类别：")
self.chk_cat.stateChanged.connect(self._on_cat_toggled)   # ← 勾选即动态展开复选框组
self.cat_checkbox_container = QWidget()                     # ← 撑开表单高度
...
for u in self._known_units:   # 20 个单位复选框直接平铺
    cb = QCheckBox(u); self.unit_checkbox_layout.addWidget(cb)
```

**影响**：
- 勾一个"要求属于类别"，表单瞬间长高，下面字段被推走，滚动位置丢失；
- 20 个单位复选框平铺，占掉半屏，与"单位"这个概念的重要性完全不成比例；
- 分区靠 `ev.addWidget(QLabel("—— 偏差率 / 编码 / 车间 / 备注 等条件 ——"))` 这种 em-dash 文本（`:112`），不是真正的分组控件；
- 8 类条件全是 AND/OR 混合语义，但只有一句文字摘要（`lbl_summary`），**没有"这条规则会命中多少条"的真实数据反馈**——用户配完规则不知道会不会误伤。

**根因**：规则条件是"实现导向"（每个字段对应一个 if 分支），不是"用户导向"（我要筛什么 → 选条件）。

### D6 · 文案与数字不一致（信任成本）

| 位置 | 文案 | 出处 |
|------|------|------|
| 看板标题 | 管理看板 · 偏差视角 **12 图** | `dashboard_dialog.py:168` |
| 悬浮按钮 tooltip | **14 图** HTML 可视化看板 | `board_visual.py:156` |
| 菜单注释 | 全量 **14 图** HTML 看板 | `board_visual.py:21` |

同一份看板，两个数字。这直接影响用户对"数据完整性"的信任。

**同类问题**：窗口标题风格三派——带 emoji（`⚙ 规则中心`、`🪪 物料画像`、`📈 数据稳定性`、`🔗 替代料长链`、`🔁 隔离区闭环`）、纯文本带副标（`隔离区 - 疑难数据暂存`）、参数后缀（`负损(含未投料)看板 - 彩罐/托盘/手包袋`）。emoji 直接进标题栏是 C 端做法，在专业工业软件里显得轻浮，且在部分 Windows 字体下会渲染成方块。

### D7 · 图表与明细脱节

**现象**：图形型看板（管理看板 12 图）在 `QWebEngineView` 里渲染 HTML，明细型看板在 `QTableView` 里渲染 Qt 表格，两者互不相通。虽然有「到主表」芯片桥（`dashboard_dialog.py:194`）做联动，但：

- 图形看板的筛选与明细看板的筛选**完全独立**（`board_visual.py:157` tooltip 明确写"与本窗口的筛选条件相互独立"）；
- 悬浮「可视化看板」按钮 v43.319 已被默认关闭，理由是"点开要走 Chromium + 12 图，首次卡死"——**说明图形看板的性能是真实障碍**。

**影响**：用户想从"哪个车间偏差大"下钻到"具体哪几条"，必须关掉图形看板、另开一个看板、重新筛一遍。

### D8 · 概览区挤占主表，且底部合计空缺

- 7 张统计卡片 + 标题行 + 进度条固定占用 175px（`layout_composer.py:317` `_right_v_splitter.setSizes([175, 625])`），表格才是这个软件的主体工作区；
- 卡片本体还有历史包袱：`stats_cards.py:3-9` 记载"旧版 7 张卡挤在一行，窄屏挤爆、宽屏拉长"，改网格后"4+3 两行装不下压扁卡片"（`:143-145`），最终挤成单行 7 列；
- v43.281 已移除底部合计标签（`version_history.py` 中"底部合计标签…整体移除"），但 `layout_composer.py:322` 仍留着 `summary_container` 占位——底部空了一行又没人用。

## 四、设计思路

### 4.1 三条原则

**① 数据密度优先于视觉呼吸**
这是生产工具，用户一天看它 6 小时。设计目标不是"留白高级"，是"一屏能看到的有效列数最大化"。参考 ui-ux-pro-max 的 Data-Dense Dashboard 规格：表格行高 36px、卡片内距 12px、网格间距 8px、字号 12–14px。**所有留白决策以"能多显示一列/多显示一行"为唯一标准。**

**② 语义色只做点缀，结构靠形状**
7 种状态色（通过/待审/预警/真异常/替代料/隔离/变更）全部收进"6px 圆点 + 状态胶囊 + accent 条"三个位置，禁止大面积填充。偏差率必须**颜色 + 数值双编码**，不让色觉障碍用户丢信息。

**③ 一次交互只解决一件事**
筛选条件、排序、分页、视图切换是四类正交操作，不能挤在同一行抢像素。

### 4.2 目标架构：三层收敛

```
┌─ L1 设计系统层 ────────────────────────────────┐
│  design-tokens（颜色/字号/间距/圆角/阴影）        │
│  light / dark 双主题，全局唯一真源                │
│  主色 #1E40AF（亮） / #4C7DFF（暗）              │
└─────────────────────────────────────────────────┘
┌─ L2 组件外壳层 ────────────────────────────────┐
│  DashboardShell   看板外壳（筛选抽屉+KPI+表格+操作条）│
│  FormShell        表单弹窗外壳（分组+固定底部条）      │
│  EvidenceShell    分析弹窗外壳（结论条+证据块+溯源）   │
│  RuleShell        规则外壳（列表+条件构建器+命中预览） │
└─────────────────────────────────────────────────┘
┌─ L3 内容层 ──────────────────────────────────┐
│  11 个看板 / 30 个弹窗 / 3 套规则 → 只写数据与图定义 │
└─────────────────────────────────────────────────┘
```

**收益量化**：6400 行的看板脚手架可收敛到约 800 行的通用外壳 + 各看板 200 行内的专属逻辑；样式改动从"改 5 处"变成"改 1 处"；看板自动获得暗色主题。

### 4.3 看板体系设计

#### 4.3.1 明细型看板（5 个）→ 统一 DashboardShell

```
┌────────────────────────────────────────────────────────────┐
│ 标题条  负损看板 · 含未投料                    [导出][全屏][关闭]│ 48px
├────────────────────────────────────────────────────────────┤
│ [🔍 筛选 (3)]  [🏭 车间: 二车间 ▾]  [📦 单位: 全部 ▾]        │ 40px
│ [已读状态: 未读 ▾]  [颜色: ●●●]  [重置]     共 12,480 条命中 │ ← 常驻筛选条
├────────────────────────────────────────────────────────────┤
│ KPI: 负损 428 条 │ 金额 -¥12.4万 │ 涉及 18 车间 │ 隔离 12     │ 54px
├────────────────────────────────────────────────────────────┤
│ 表格（sticky 表头 32px / 行高 36px / 斑马纹 / 悬停高亮）        │
│                                                            │
├────────────────────────────────────────────────────────────┤
│ 操作条  已选 0 / 428   [加入隔离区] [标记已读] [导出所选]  关闭 │ 40px
└────────────────────────────────────────────────────────────┘
```

**关键改动**：13 个平级筛选控件 → **3 个常驻下拉 + 1 个「筛选」抽屉按钮**。抽屉里按语义分三组（物料维度 / 数值维度 / 组织与状态维度），每个下拉带命中计数，括号里显示"当前生效 3 个条件"，点开抽屉能一次看到全部条件。**常驻区永远不超过 6 个控件，宽度需求从 3153px 降到约 900px，彻底摆脱横向滚动。**

这同时解掉了 D2 的"尺寸红线"——筛选控件从"一行平铺"变成"下拉"，下拉可以放心写 padding / border-radius / 圆角而不触发 sizeHint 崩塌，视觉统一才有可能。

#### 4.3.2 图形型看板（管理看板）→ 图表明细双联

放弃"图形看板独立存在"的模式，改成**同一个窗口里上下分栏**：

```
┌──────────────────────────────────────────────────────┐
│ 图表区（QWebEngineView，12 图，2×6 网格）              │ 55%
│  图表点击 → 选中该维度 → 下方表格自动过滤            │
├──────────────────────────────────────────────────────┤
│ 明细表（复用主表模型 + 同一筛选状态）                   │ 45%
└──────────────────────────────────────────────────────┘
```

**收益**：图表与明细共享筛选状态，"哪个车间偏差大 → 点开看具体哪几条"一次完成；关闭了 D7 的脱节。同时保留「导出 HTML」按钮（现有能力不丢）。

**性能对策**：图表区按需渲染，默认只渲染当前分厂，切换分厂用 WebEngine 的 `setHtml` 增量替换，不重建整个页面；WebEngine 不可用时降级到静态 HTML + QTextBrowser（现有降级路径保留）。

#### 4.3.3 专题型看板（5 个）→ 统一"专题报告页"

数据稳定性 / 隔离区闭环 / 替代料长链 / 翻箱守恒 / 物料画像 —— 这五个的共同特征是**先给结论、再给证据、最后给动作**。统一为：

```
┌────────────────────────────────────────────────┐
│ 结论条  ⚠ 翻箱守恒异常 3 例，净含量超投 ¥4,820  │ ← 大字结论 + 语义色
├────────────────────────────────────────────────┤
│ 证据块（图表 / 时间线 / 溯源链）                 │
├────────────────────────────────────────────────┤
│ 明细表                                        │
├────────────────────────────────────────────────┤
│ 操作条  [加入隔离区] [标记已读] [生成报告]        │
└────────────────────────────────────────────────┘
```

物料画像同理：结论条显示"该物料近 30 天偏差 12 次，占用净额 ¥8,340"，下面是它的偏差时间线 + 历史记录。

### 4.4 弹窗体系设计

| 类型 | 外壳 | 关键规范 |
|------|------|---------|
| **表单型** | FormShell | 标题（图标 + 名称 + 可选副标）→ 滚动内容区（真分组控件，不是文字标题）→ 固定底部条（右「取消/保存」，左「改动预览」） |
| **分析型** | EvidenceShell | 结论条（大字结论 + 语义色）→ 证据块（分组展开）→ 溯源链（时间线 + 来源）→ 底部操作 |
| **批量型** | BatchShell | **影响范围预览**（"将影响 37 行，其中 5 行已审核"）→ 可选项 → 危险操作二次确认 |
| **确认型** | QMessageBox 统一模板 | 主操作按钮在右；文案句式统一为「动词 + 对象 + 结果」；错误弹窗必须带可复制的技术详情折叠区 |

**尺寸规范**：
- 小表单 420×520｜中表单 720×560｜大型分析 960×640｜看板 1440×900 起步（可最大化）
- 全部弹窗统一 `setWindowFlag(Qt.WindowMinMaxButtonsHint)` 策略：内容会超出一屏的给最大化，纯表单不给（避免"表单被拉成巨幅空白"）

## 七、必须守住的约束（红线）

这些是历史事故换来的，任何设计改动都不能违反：

1. **看板筛选栏的 sizeHint 精度**——现在靠"不下沉平铺控件"才保住不重叠（`board_visual.py:36-42`）。改用抽屉后此约束自然解除，但迁移期每次改动都要跑 offscreen 尺寸断言。
2. **禁止裸 `QFrame { color: ... }`**——QTableView/QLabel/QScrollArea 都是 QFrame 子类，这条规则会把表格数据冲成浅色（实测深色像素占比 7.27% → 0.00%，`board_visual.py:84-87`）。
3. **QSS 里给控件写 border/padding 会改 sizeHint**——按钮 80×20 → 24×12、下拉 66×22 → 56×18，所有「写尺寸」的 QSS 都要在布局精算过的控件上避开。
4. **QSS 特异性要带 ID 前缀**——裸 `QPushButton#id`（1 ID + 1 元素）会输给 `QDialog#id QPushButton`（1 ID + 2 元素），导致按钮白底（`board_visual.py:125-129`）。
5. **隔离区「实际=0」语义**：实际=0 须人工审计，绝不自动已读、绝不判为已解决——任何涉及异常态的视觉编码不得暗示"已处理"。
6. **偏差率口径**：排除 |偏差率| 恰为 100% 的 SAP 除零钳位假值与实际=0 的未投料行，视觉高亮必须与代码同口径，否则用户会按错误的颜色去查数据。

## 八、一句话总结

> 这套软件的问题不是"配色旧"，是**没有壳**：11 个看板、30 个弹窗、3 套规则各自长各自的模样，样式改不动是因为结构没收敛。
> **先建 DashboardShell / FormShell / EvidenceShell / RuleShell 四个外壳，再把 6 种蓝色收敛成 1 种、把 12 套筛选形态收敛成 1 种、把 5 个入口收敛成 1 种**——这一步做完，后面的美化都是水到渠成的事。
