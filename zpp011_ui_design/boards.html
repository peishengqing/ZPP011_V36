形态 A 五要点

1
标题条统一

去掉 emoji，改「名称 · 副标题」；副标题用灰字承载口径说明（如「彩罐 / 托盘 / 手包袋」），不再塞进窗口标题栏撑宽度。

2
常驻筛选条 ≤ 6 控件

只留最高频的 4 个 + 「筛选」抽屉按钮，右侧显示「命中 N / 总数」，随时知道筛掉了多少。

3
KPI 带 54px

4–5 个关键量一行放完：条数、金额、其中未投料、涉及车间、已隔离。点 KPI 即下钻筛选。

4
表格为绝对主角

sticky 表头 32px、行高 36px、斑马纹、悬停高亮；未投料行（实际=0）单列「未投料」状态，不与真异常同色——避免用户误判处置优先级。

5
操作条承载写操作

加入隔离区 / 标记已读 / 导出所选 三个写操作统一收在底部，右侧显示快捷键。选中行数实时显示在左。

图表点一下，明细立刻跟上

现状图形看板（dashboard_dialog.py，QWebEngineView 渲染 12 图）与明细看板的筛选完全独立，用户想从「哪个车间偏差大」下钻到「具体哪几条」，必须关掉图形窗口、另开一个看板、重新筛一遍。新版上下分栏、共享状态，图表点击即联动过滤。
性能对策：图表区按需渲染（默认只出当前分厂，切换分厂用增量 HTML 替换而非重建页面），WebEngine 不可用时降级到静态 HTML + QTextBrowser（沿用现有降级路径）。

专题型统一骨架

7
结论条先行

大字结论 + 语义色 + 关键数字（金额/数量）。用户 3 秒内知道「有没有问题、有多严重」。这一条是专题型看板与明细型看板的根本区别：明细型让用户自己找异常，专题型直接把异常端上来。

8
证据块 + 溯源链

结论必须能被质疑——给出测算图、来源链路（哪张单、哪一步、为什么这样判）。现有「数据稳定性」「隔离区闭环」「物料画像」各自有证据，但排布方式各异；统一成「测算块 + 溯源块」两栏。

9
底部动作与明细型一致

加入隔离区 / 标记已读 / 生成报告 三个写操作，三类看板行为一致，用户不需要重新学。

语义色纪律（专题型尤其重要）：「未投料（实际=0）」与「真异常」在颜色上必须可区分——前者是机械结果需人工审计、后者是真问题。二者若同色，用户会按错误优先级去查数据。
