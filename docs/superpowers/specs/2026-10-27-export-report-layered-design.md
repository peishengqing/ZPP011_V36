# 导出报表「分层报告化」改造 — 设计规格

日期：2026-10-27 ｜ 状态：已获用户口头批准（"可"）｜ 版本落点：v43.283+

## 1. 背景与目标

ZPP011 偏差分析器导出的 Excel（12 个 sheet）目前是"平铺的数据堆"：
领导要自己从 8400 行明细里找结论，执行层没有可直接当任务清单用的页面，
趋势页 42% 空白格、汇总页排序混乱。

目标：把报表改造成**三层结构**——

| 层 | 受众 | 载体 |
|---|---|---|
| 结论层 | 领导/周报 | 升级现有 📊 驾驶舱 |
| 派活层 | 车间主任/工艺员 | 新增 📌 订单透视、🏭 车间透视 两页 |
| 数据层 | 分析/追溯 | 现有明细页只做降噪，结构不动 |

成功标准：领导打开文件 30 秒内能说出"哪里最严重、比上期好没好"；
执行层能拿订单透视页从上往下打勾干活。

## 2. 铁律（红线）

1. **零口径改动**：所有新内容只从现有中间变量（dev_df / summary_rows 等）
   派生呈现，不新增业务计算、不碰 analyzer 业务逻辑。
   **唯一例外（用户 2026-10-27 批准）：偏差等级列**，见 §2.1。
2. **现有 12 页数值逐格 diff 必须为零**（只允许改排序展示、格式、填"—"、
   挪说明行，不允许改任何单元格数值）。完整偏差明细新增的
   「偏差等级」列在白名单内（新列，不属于"改动现有数值"）。
3. 全部新页在 `analysis/excel_builder/post_process.py` 生成（呈现层），
   延续 `_add_dashboard` 的既有模式；`ZPP011_SKIP_POST_PROCESS=1` 时
   整体可跳过。

### 2.1 偏差等级列（唯一业务层例外）

- 位置：`analysis/analyzer.py` 主表计算段新增列 `偏差等级`，
  软件主表 / 完整偏差明细 / 订单透视 共用同一列（单一事实源，无双口径）。
- 规则（对现有「偏差率(%)」列的确定性分档，不引入新数据）：
  - |偏差率| > 50% → `严重`
  - 10% ≤ |偏差率| ≤ 50% → `一般`
  - |偏差率| < 10% → `轻微`
  - 偏差率为空/非数值 → `—`
- 边界说明：±100% 钳位标记行（定额=0 → +100%、实际=0 → −100%，约 2636 行）
  按规则归入 `严重`——它们本就是最需要人看的行，分档语义正确，不做特判。
- GUI 同步：主表列顺序与「偏差区间」相邻展示；筛选面板可按等级筛选
  （复用普通列筛选通道，零新机制）。
- 阈值 50/10 为初始值，做成 analyzer 模块常量（`GRADE_BOUNDS = (10, 50)`），
  业务要调只改一处。

## 3. 第 1 层 · 驾驶舱升级（结论页）

在 v43.241 KPI 块基础上扩成完整一页周报，自上而下：

1. **KPI 行**（4 个，已有）：总偏差记录 / 正偏差金额 / 负偏差金额 /
   无备注预警条数。每个 KPI 下新增一行**环比**：
   - 数据源：**新增期次快照机制**——审核库（audit.db）只存已读状态/快照，
     不存偏差数据，无法回查上期聚合。故每次导出成功后，把本期 KPI 聚合
     （日期范围 + 4 项指标）以 upsert 写入 audit.db 新表
     `export_snapshots(period_start, period_end, created_at, kpi_json)`；
     下次导出时取"结束日期早于本期起点"的最近一条作为上期。
     该表是纯呈现辅助（不参与任何业务口径），建表迁移沿用
     read_status.py 现有 `_ensure_column` 幂等模式。
   - 取不到（首期/无历史快照/异常）→ 显示灰字"首期无环比"，不报错；
   - 显示格式：`▲ +12.3%`（红，恶化）/ `▼ -8.1%`（绿，好转）/ `— 持平`
     （|变化|<0.5%）。方向语义：金额类绝对值增大=恶化。
2. **Top 5 车间表**：按 |总偏差金额| 降序取 5 行（车间/条数/金额/备注覆盖率），
   金额列带数据条。
3. **Top 10 物料表**：按 |偏差金额| 降序取 10 行（编码/名称/金额/占总额比），
   末行给"前 10 合计占比"（帕累托一眼看钱漏在哪）。
4. **周趋势图**：现有 3 张日级 BarChart 改为**自然周聚合**（ISO 周，
   周一为界）：条数一张、金额一张；日级 1077 行噪声大，周级看走向。

## 4. 第 2 层 · 派活页（新增 2 个 sheet）

### 4.1 📌 订单透视

- 粒度：一行一个流程订单。
- 列：订单号 / 订单日期 / 工厂 / 车间 / 偏差条数 / 净偏差金额 /
  备注覆盖率 / **状态**。
- 状态定义：未填备注条数 > 0 → `🔴 待核实`；否则 → `🟢 已闭环`。
- 排序：|净偏差金额| 降序（最痛的订单在最上面）。
- 冻结表头 + autofilter + 行高亮（待核实行浅橙底）。
- **数据源**：以「完整偏差明细」sheet 的行集为输入（post_process 读回该页
  数据派生，与主表 dev_df 行集一致），不重新跑口径。
  注：完整偏差明细已剔除替代料，故订单透视的"偏差条数"不含替代料行——
  这是有意口径（派活清单只关心需要人工核实的非替代料偏差），文档化于此。

### 4.2 🏭 车间透视

- 交叉表：行 = 车间，列 = 最近 4 个自然周，格 = 该车间该周净偏差金额。
- 热力着色：三色阶（红=金额绝对值大/恶化，白，绿=小/好转），
  用 openpyxl ColorScaleRule 实现。
- 列头带周区间标注（如 `W44 10/27-11/02`）。
- 最右列：环比方向箭头（本周合计 vs 上周合计）。

## 5. 第 3 层 · 数据层降噪（不新增页，只调呈现）

| 页 | 改动 |
|---|---|
| 汇总统计 | 展示行按 \|总偏差金额\| 降序重排（由 post_process 对**已生成的 worksheet 整行搬移**完成，不改 sheet1_summary 业务代码，序号列随行走）；备注覆盖率列加数据条；数值零改动 |
| 趋势分析（自然日分组） | R2 说明文字挪到表头上方注释或分析说明页；42% 空白格填 `—`；补 autofilter |
| 完整偏差明细 | 列宽按内容微调；冻结/筛选已有，不动 |

## 6. 视觉统一规范（贯穿三层）

- 对齐：数字右、文本左（openpyxl Alignment）。
- 格式：金额 `#,##0.00`、比率 `0.00%`（沿用 post_process 现有实现）。
- 新增元素：
  - 数据条 DataBarRule 表达量级；
  - 三色阶 ColorScaleRule 表达环比方向；
  - 每页 A1 上方一行 10px 灰字"本页讲什么"（一句话）；
  - 页签分色 `sheet_properties.tabColor`：结论页绿 `2E7D32` /
    派活页橙 `E65100` / 数据页灰 `9E9E9E`。

## 7. 实现落点

- `analysis/excel_builder/post_process.py`：新增 4 个函数
  （`_upgrade_dashboard`、`_add_order_pivot_sheet`、`_add_workshop_pivot_sheet`、
  `_denoise_data_sheets`），挂进 `decorate_workbook` 主流程，各自 try/except
  独立降级（单页失败不拖垮整体，沿用现有模式）。
- `analysis/analyzer.py`：`export_full_report_from_intermediates` 把 dev_df /
  summary_rows 等中间变量传给 post_process（现有传参通道扩展，不改计算）。
- 环比数据：新增 `core/period_stats.py`——`save_export_snapshot()`（导出成功后
  upsert 本期 KPI 聚合到 audit.db 的 export_snapshots 表）与
  `load_previous_snapshot(period_start)`（取上一期）。快照写入失败静默降级
  （显示"首期无环比"），绝不影响导出主流程。
- 预估规模：post_process +350 行左右，新 sheet 2 个，版本号 v43.283（第 1+3 层）
  / v43.284（第 2 层）。

## 8. 分期

- **一期（v43.283）**：驾驶舱升级 + 数据层降噪 + 视觉规范 + **偏差等级列**
  （§2.1，唯一业务层例外，analyzer 加列 + GUI/导出共用）。
- **二期（v43.284）**：订单透视 + 车间透视两个新页 + 环比（依赖 SQLite 快照）。
  一期人眼验收后再做。
- **明确不做（用户 2026-10-27 决策）**：责任归属列（缺主数据源）、
  异常阈值/净口径重定义（真口径决策，不在本项目擅自引入）。

## 9. 测试与验收

1. 端到端：真实源数据（E:\ZPP011导出文件原数据\ZPP011_20261001-20261022.xlsx）
   生成 → openpyxl 读回断言：
   - 新 sheet 存在、tabColor 正确；
   - Top5/Top10 排序单调性；
   - 订单透视状态列与"未填备注>0"一致性；
   - 环比首期容错（清库模拟）；
   - 空白格填 `—`、autofilter 存在。
2. 回归铁律：改前/改后各生成一份，现有 12 页**数值**逐格 diff = 0
   （格式/排序列宽差异白名单化；完整偏差明细新增「偏差等级」列在白名单）。
3. 偏差等级单测：边界值 9.99/10/50/50.01、空值、±100 钳位行 → 分档正确；
   analyzer 与 GUI 主表读同一列（防双口径）。
4. 人工验收：用户打开 Excel 人眼过一遍，按观感微调一轮。

## 10. 已决策项（头脑风暴问答记录）

- 加工方向：加透视汇总页 + 排版可读性 + 增强可视化（不加业务列）。
- 受众：领导 + 执行层都要 → 分层设计。
- 透视维度：车间 / 物料 Top / 订单 / 时间趋势 四项全要（订单/车间进新页，
  物料 Top/趋势进驾驶舱）。
- 路线：用户授权自由发挥（"可以加页，你想怎么搞都行"），采用
  "现有页重构 + 新增派活页"混合路线。
